## 2. Architectural Role & Boundary

The Browser Reverse Engineering Toolkit Adapter provides a clean, provider-neutral bridge connecting bulk offline capture packages generated by `SiteSnapshotter`, `SiteCrawlerSnapshotter`, or `SiteReconstructor` to REA's evidence and knowledge modeling layers.

```
┌────────────────────────────────────────────────────────┐
│             REA Main Orchestrator (Core)               │
└──────────────────────────┬─────────────────────────────┘
                           │ controls
            ┌──────────────▼──────────────┐
            │   REA Evidence Repository   │◄────────────────┐
            │  (Ledger, Graph, IR, Gates) │                 │
            └──────────────▲──────────────┘                 │
                           │                                │
            ┌──────────────┴──────────────┐                 │
            │   REA Native MCP Provider   │                 │
            │     (rea-agents@6.8.0)      │                 │
            └─────────────────────────────┘                 │
                                                            │ Normalizes &
                                                            │ tags IMPORTED
                                              ┌─────────────┴─────────────┐
                                              │ Optional Browser Toolkit  │
                                              │    Adapter (rea-bret)     │
                                              └─────────────▲─────────────┘
                                                            │ Reads captures
                                              ┌─────────────┴─────────────┐
                                              │ Dvurechensky/BRET Capture │
                                              │  (Offline folder / JSON)  │
                                              └───────────────────────────┘
```

### Core Invariants:
1. **REA Remains Supreme:** REA is the primary orchestrator, evidence authority, and analysis engine. The toolkit is a supporting offline capture source only.
2. **Strictly Optional:** REA core operates fully without this adapter.
3. **No Mandatory Playwright/CDP:** Core REA never depends on Playwright or Puppeteer. The adapter operates purely as an offline file parser.
4. **Provenance Transparency:** No imported observation is ever represented as a direct REA observation (`OBSERVED`). All imported data carries label `[IMPORTED]` or `[INFERRED]`.

## 2. Ingestion Pipeline

The adapter processes external capture bundles through a five-stage pipeline:

```
[1. Archive Validation] ──> [2. Sanitization Gate] ──> [3. Normalization] ──> [4. Deduplication] ──> [5. Ledger Ingestion]
```

### Stage 1: Archive Validation & Integrity Verification
- Reads the supplied capture directory (e.g. `./captures/my-site-capture/`).
- Computes SHA-256 digests of all raw capture manifests (`capture.json`, network logs, storage dumps).
- Records capture metadata: recording date/time, user agent, viewport settings, crawl depth.

### Stage 2: Security & Sanitization Gate
- **PII & Secret Scrubbing:** Scans all captured headers, storage keys, and request/response payloads.
- Redacts cookies, authorization tokens (`Bearer ...`, JWTs), passwords, API keys, and personal data.
- Replaces raw values with type-only schemas (e.g. `{ "token": "[REDACTED_SECRET]" }`).

### Stage 3: Entity Normalization
- Maps raw capture objects into standardized REA schemas:
  - URLs & route structures → `Route` attributes & `navigatesTo` edges.
  - HTML & rendered DOM trees → `inspect.dom` evidence & component candidates.
  - Network transactions → `inspect.network-log` and `apiDependencies`.
  - Application storage dumps → `inspect.storage` key definitions.
  - Asset payloads → `asset-register.md` entries with `provenance: "external-capture"`.

### Stage 4: Deduplication & Cross-Referencing
- Compares imported URLs and APIs against existing REA native observations.
- Discards duplicate entries while enriching existing nodes with external confirmation references.

### Stage 5: Ledger Ingestion
- Assigns sequential REA Evidence IDs (`E-xxx`).
- Writes normalized records into `evidence-ledger.md` and appends graph fragments into `graph/fragments/`.

## 4. Unsupported Fields & Graceful Degradation

The Browser Toolkit records certain browser internals and engine-specific states that REA does not ingest:
- **CDP Session Handles:** Discarded (not relevant to offline analysis).
- **V8 Heap Snapshots:** Discarded (out of scope for frontend reconstruction).
- **Binary Image/Media Blobs:** Stored as external asset references; raw bytes are not loaded into markdown or JSON ledger fragments.
- **Unverified OpenAPI Inferences:** If `SiteReconstructor` outputs a speculative OpenAPI schema, it is imported as `[INFERRED]` with `Confidence: Low` until cross-checked against actual HTTP traffic logs.
